# Plan: Ansible Migration — Step 02: K3s Install

## Request
Automate K3s installation on masters + agents via Ansible. Depends on Step 01 (MariaDB running at `10.27.10.50:3306`).

## Reference (from README.md)

### First master (bootstrap)
```bash
curl -sfL https://get.k3s.io | \
  K3S_DATASTORE_ENDPOINT='mysql://k3s:k3spass@tcp(10.27.10.50:3306)/k3sdb' \
  K3S_KUBECONFIG_MODE="644" \
  sh -s - server \
  --tls-san 10.27.10.50 \
  --disable traefik --disable servicelb --disable local-storage
```

### Other masters
Same + `--token=<token>` flag.

### Agents
```bash
curl -sfL https://get.k3s.io | \
  K3S_URL=https://10.27.10.50:6443 \
  sh -s - agent \
  --token=<token>
```

## Implementation Steps

### Step 1 — Update group_vars/all.yml
Add:
```yaml
# K3s
k3s_version: ""                     # empty = latest stable
k3s_datastore_endpoint: "mysql://k3s:k3spass@tcp(10.27.10.50:3306)/k3sdb"
k3s_tls_san: "{{ docker_host_ip }}" # 10.27.10.50 (HAProxy LB IP)
k3s_disable:
  - traefik
  - servicelb
  - local-storage
k3s_flannel_backend: host-gw        # ← fix for Ubuntu 26.04 kernel 7.0.0
k3s_token_file: /tmp/.k3s-token     # local file to pass token between plays
k3s_server_url: "https://{{ docker_host_ip }}:6443"
```

### Step 2 — Create k3s role

#### `roles/k3s/defaults/main.yml`
```yaml
---
k3s_role: server                    # "server" or "agent"
k3s_token: ""
k3s_version: ""
k3s_datastore_endpoint: ""
k3s_tls_san: ""
k3s_disable: []
k3s_flannel_backend: host-gw
k3s_config_dir: /etc/rancher/k3s
k3s_binary: /usr/local/bin/k3s
k3s_service: k3s                    # k3s for server, k3s-agent for agent
```

#### `roles/k3s/tasks/main.yml`
Tasks:

1. **Create config directory** — `file` module, path `{{ k3s_config_dir }}`, state directory
2. **Deploy config.yaml** — `template` module, src `config.yaml.j2`, dest `{{ k3s_config_dir }}/config.yaml`. Only for `k3s_role == server`.
3. **Build install command** — Complex command construction with conditionals:
   - `INSTALL_K3S_VERSION` if `k3s_version` is set
   - For server: `K3S_DATASTORE_ENDPOINT`, `K3S_KUBECONFIG_MODE=644`, `--tls-san`, `--disable` flags, `--token` (if joining)
   - For agent: `K3S_URL`, `--token`
4. **Check if installed** — `stat` module on `{{ k3s_binary }}`
5. **Install K3s** — `shell` module with the curl pipe command. When: not already installed.
6. **Wait for ready** — `wait_for` module on port 6443 (for server) or `command: k3s kubectl get nodes` for server
7. **Fetch node-token** — For bootstrap master only, read `/var/lib/rancher/k3s/server/node-token` via `slurp`, save to local file via `copy` + `delegate_to: localhost`. Only when `k3s_role == server` and it's the bootstrap node.
8. **Kubeconfig** — Copy `/etc/rancher/k3s/k3s.yaml` to `~/.kube/config` on the control node (optional convenience)

#### `roles/k3s/templates/config.yaml.j2`
```yaml
# Generated by Ansible
{% if k3s_flannel_backend %}
flannel-backend: {{ k3s_flannel_backend }}
{% endif %}
```

#### `roles/k3s/meta/main.yml`
Standard metadata, no dependencies (unlike Step 01 roles which depend on docker).

### Step 3 — Create playbook `02-k3s.yml`

Three plays:

```yaml
# Play 1: Bootstrap first master only
- name: Bootstrap first K3s server
  hosts: masters
  max_fail_percentage: 0
  serial: 1                     # run one at a time — first bootstraps, others wait
  tasks:
    - name: Wait for MariaDB to be reachable
      wait_for:
        host: "{{ docker_host_ip }}"
        port: 3306
        timeout: 120
      delegate_to: localhost
      run_once: true
    
    - name: Include k3s role (bootstrap first master)
      ansible.builtin.include_role:
        name: k3s
      vars:
        k3s_role: server
        k3s_token: ""          # no token for bootstrap
      when: inventory_hostname == groups['masters'][0]
```

Wait, the problem with `serial: 1` and `when` conditions is complex. Better to split into separate plays.

Better approach — clean separation:

```yaml
# Play 1: Bootstrap first master
- name: Bootstrap first master
  hosts: masters[0]          # targets only the first master (k3s-m1)
  gather_facts: yes
  roles:
    - role: k3s
      vars:
        k3s_role: server
        # No token — this is the bootstrap

# Play 2: Register node-token to local file
- name: Fetch node-token from bootstrap master
  hosts: masters[0]
  gather_facts: no
  tasks:
    - name: Read node-token
      slurp:
        src: /var/lib/rancher/k3s/server/node-token
      register: node_token_raw
    
    - name: Save token to control node
      copy:
        content: "{{ node_token_raw.content | b64decode | trim }}"
        dest: "{{ k3s_token_file }}"
      delegate_to: localhost

# Play 3: Join remaining masters
- name: Join remaining masters
  hosts: masters:!masters[0]  # all masters except first
  roles:
    - role: k3s
      vars:
        k3s_role: server
        k3s_token: "{{ lookup('file', k3s_token_file) }}"

# Play 4: Join agents
- name: Join agents
  hosts: workers
  roles:
    - role: k3s
      vars:
        k3s_role: agent
        k3s_token: "{{ lookup('file', k3s_token_file) }}"
```

**Important limitation:** `masters[0]` indexing requires `ansible_user` to have access to all masters. The first master in the inventory (`k3s-m1`) must be the one that bootstraps. This matches the README (master one = first master).

## Execution Order (Crucial)

1. MariaDB must be running (Step 01) — verify with `wait_for` port 3306
2. First master bootstraps → creates cluster + token
3. Token fetched → saved locally
4. Remaining masters join with token
5. Agents join with token

## Risks / Open Questions

1. **`masters[0]` reliability** — Inventory order defines who is `masters[0]`. Must be k3s-m1. Documented in plan.
2. **Token security** — Written to `/tmp/.k3s-token` on control node. Plaintext. Acceptable for homelab v1.
3. **Idempotency** — `curl | sh` is safe to re-run (K3s detects existing install). Added `stat` check to skip.
4. **Config file persistence** — `config.yaml` written before install. K3s reads it at startup. If file changes after install, K3s needs restart. Best-effort for now.
5. **K3s version** — Empty = latest. Can pin via `k3s_version` var.
6. **Agent token** — Same token for both masters and agents (from `/var/lib/rancher/k3s/server/node-token`). This is K3s default behavior.
